# Bashiiin! coffee LP デザイン定義書

**Version 1.3 / 2026-09-13**  
**Document status: Production Design Direction**  
**連携資料：Bashiiin! coffee LP 正式制作版 要件定義書 v1.3**

> この文書は、後工程でPC版・モバイル版の「完成イメージ画像」を制作し、その後に実装へ落とし込むための視覚判断基準である。

## 0. デザインの目的

### 0.1 サイトの目的

サイトの第一目的は、**Bashiiin! coffeeのスペシャルティコーヒーへのこだわりを、初めての人にも短時間で理解できる形にし、来店検討につなげること**。

第二目的は、営業情報、豆、スイーツ、店内、カルチャー、Instagram、問い合わせを、迷わず使える1ページに整理すること。

### 0.2 伝えたい印象

正式版で伝えたい印象は、次の5語に固定する。

1. **CLEAR / 明瞭** — 情報が迷わず読める
2. **BRIGHT / 明るい** — 白を基調に、開かれた印象
3. **CRAFT / 丁寧** — コーヒーの専門性と手仕事を感じる
4. **WARM / 温かい** — 無機質な白ではなく、写真と生成りで温度を持たせる
5. **PLAYFUL / 遊び心** — CULTURE等でBashiiin!らしい自由さを残す

「高級」「暗い」「隠れ家」「静寂」は中心価値にしない。

### 0.3 一文コンセプト

**EVOLUTION, NOT REINVENTION. / WHITE SPACE, SERIOUS COFFEE, PLAYFUL CULTURE.**

営業サンプルLPで評価されたBashiiin! coffeeらしさを捨てず、白い余白と明瞭なUIで正式版へ進化させる。コーヒーは真面目に、カルチャーは少し自由に見せる。

### 0.4 営業サンプルLPからの継承原則

先方は現行営業サンプルLPを確認したうえで契約に進んでいる。したがって正式版は、一般的な白いカフェサイトへ作り替えるのではなく、**営業サンプルのデザインDNAを維持したまま明るく洗練する**。

継承する要素：

- 実店舗・実商品の写真を大胆に使う構成
- 大きな明朝系の日本語見出し
- 英字Eyebrowと細いrule等の編集的ディテール
- Bashiiin! coffeeロゴの存在感
- 写真とタイポグラフィの強いコントラスト
- 雑誌・エディトリアルを思わせる余白設計
- 木・コーヒー・店内の温度感、クラフト感、文化性

変更する要素：

- 黒背景中心から、白・生成り主体へ移行する
- 旧コピーの「隠れ家」「少し奥」「一人でふらり」等は使わない
- ACCESS独立セクションを削除し、正式要件に沿ったCURRENT BEANS／CULTURE／CONTACTを追加する
- 各セクションの情報設計と操作性を正式サイト向けに整理する

**白くすること自体を目的にしない。営業サンプルとの連続性が失われる変更は避ける。**

## 1. 参照するデザインシステムの考え方

本サイトは、デジタル庁デザインシステムとPayPayが公開しているデザイン運用の考え方を**原則・設計思想として参照**する。各組織のブランドカラー、ロゴ、コンポーネント外観を模倣するものではない。

### 1.1 デジタル庁デザインシステムから参照する原則

[DADS-01] 個別サイトではデザインシステムをそのまま貼り付けるのではなく、ブランド・情報設計に合わせてスタイルガイドを作る。  
[DADS-02] カラーは役割を定義し、アクセントカラーを多用しない。  
[DADS-03] 余白を情報の階層・可読性・関係性の表現として使い、一定のルールで運用する。  
[DADS-04] PrimaryとSecondaryの操作は色だけでなく、塗り／アウトライン等の形でも区別する。  
[DADS-05] テキストは背景とのコントラスト4.5:1以上、非テキストUIは3:1以上を基本とし、色だけで意味を伝えない。  
[DADS-06] タイポグラフィは一貫性・可読性・情報階層を優先する。

### 1.2 PayPayの公開デザイン事例から参照する原則

[PP-01] デザインシステムで色・タイポグラフィ・コンポーネントを共通化し、一貫性を保つ。  
[PP-02] UIを作る前にユーザーの課題と目的を明確にする。  
[PP-03] 新しいUIは既存のシステムとの整合性を確認し、デザインレビュー・文言チェックを行う。  
[PP-04] 「単純化すること」だけを目的にせず、ユーザーが安心できる確認・情報階層を残す。  
[PP-05] 画面単位ではなく、将来の拡張・再利用を考えてコンポーネント化する。

### 1.3 Bashiiin! coffeeへの翻訳

- 行政サイトのような無機質さにはしない
- 決済アプリのようなプロダクトUIをそのまま持ち込まない
- **分かりやすい情報階層、余白、UIの一貫性、アクセシビリティ**だけを土台として借りる
- その上に、Bashiiin!の写真、ロゴ、コーヒー、グラフィックの個性を重ねる
- デジタル庁／PayPayの設計思想は、営業サンプルLPのブランド表現を上書きするものではない
- 作成済みデザインリファレンスは、営業サンプルのDNAと本書の原則を具体化した視覚参考として利用する
- 要件・店舗回答とデザインリファレンスが競合する場合は、要件・店舗回答を優先する

## 2. ビジュアルトーン

### 2.1 全体比率

**80%：白・ニュートラル・写真・タイポグラフィ**  
**20%：ブランドアクセント・カルチャー表現**

比率は厳密な面積計算ではなく、ページ全体の明暗バランスの目安とする。ページを全面的に白く均すのではなく、写真やSPACE等で営業サンプルの深いトーンを局所的に残す。アクセントは「重要性」または「セクションの気分」を変える目的に限定する。

### 2.2 やってはいけない方向

- 全面黒背景
- HEROを黒グラデーションで覆う
- バー・夜営業のような暗いムードを主役にする
- 和風・京都観光サイト風の装飾
- ベージュ一色の韓国カフェ風
- 金色を多用した高級カフェ風
- すべてのセクションで違う色・違う装飾を使う
- UIより装飾を優先し、情報が読みにくくなること
- 過剰なコラージュ、ステッカー、回転文字、常時アニメーション
- 一般的な白いカフェテンプレートへ寄せ、営業サンプルの個性を消すこと
- すべてのセクションを「左テキスト＋右写真」など同一構図で繰り返すこと

## 3. カラーシステム

以下は**デザインモック用の初期トークン**。実装時に写真・ロゴとの相性とコントラストを再確認して微調整してよい。

| Role | Token | 初期値 | 用途 |
|---|---|---:|---|
| Canvas | `--bg` | `#FAFAF7` | ページ基調の温かい白 |
| Surface | `--surface` | `#FFFFFF` | カード、フォーム |
| Text | `--ink` | `#1D1D1B` | 本文、主要見出し |
| Muted | `--muted` | `#6B6B64` | 補助文、metadata |
| Line | `--line` | `#E4E2DA` | 区切り線、カードborder |
| Warm | `--cream` | `#F3EEE4` | SWEETS、温度感 |
| Coffee | `--coffee` | `#4A3427` | コーヒー由来の深い補助色 |
| Orange | `--accent-orange` | `#C85B2C` | CTAやCULTUREの小アクセント |
| Blue | `--accent-blue` | `#2F66B3` | 原則UIでは常用しない。素材・限定グラフィックで必要時のみ |
| Green | `--accent-green` | `#3F7357` | 原則UIでは常用しない。素材・限定グラフィックで必要時のみ |

### 3.1 カラールール

- 本文色は`--ink`を基本
- Primary CTAは`--ink`背景＋白文字を第一候補とし、アクセント色を常用しない
- Secondary CTAは白背景＋`--ink`アウトライン
- UIの主アクセントはBurnt Orangeを基本とする。Blue / Greenは常設UIでは原則使わず、写真・商品パッケージ・限定グラフィック等に必要な場合のみ使用する
- 色だけで状態・重要度を表現しない
- リンクはテキストリンクと分かる下線・アイコン等を併用
- 写真の色味は自然さを優先し、極端なティール＆オレンジや暗色加工を避ける

## 4. タイポグラフィ

### 4.1 基本

- 日本語Display見出し：`Noto Serif JP`, `Hiragino Mincho ProN`, `Yu Mincho`, serif相当を第一候補とし、営業サンプルの大きな明朝系見出しを継承する
- 日本語本文・UI：`Noto Sans JP`, `Hiragino Kaku Gothic ProN`, `Yu Gothic`, sans-serif 相当
- 英字Eyebrow／UI：sans-serif系を基本とし、letter-spacingで編集的な表情を作る
- 外部Webフォントは必須にしない。導入する場合も表示速度とフォールバックを考慮する
- 筆記体はSWEETS／CULTURE等の補助装飾に限定し、主要情報には使わない
- Display用に過度な装飾書体を使用しない

### 4.2 情報階層

**Desktop目安**

- H1：56–72px / 1.05–1.15
- H2：40–52px / 1.15–1.25
- H3：24–30px
- Body：16–18px / 1.75–1.9
- Meta / Eyebrow：12–14px / tracking +0.08em〜0.14em

**Mobile目安**

- H1：38–48px
- H2：30–38px
- Body：16px以上
- Meta：12–13px

### 4.3 文字表現

- 英字見出しは装飾ではなく、セクション識別として使用
- 日本語本文を極端に細くしない
- 長文の中央揃えを避ける
- 重要情報は短い段落＋見出し＋余白で整理する
- 価格を載せないため、カード内に「¥」等のダミー表記を入れない

## 5. 余白・レイアウト・形状

### 5.1 Spacing scale

本プロジェクト独自の運用トークンとして8pxを基本単位とし、`8 / 16 / 24 / 32 / 48 / 64 / 80 / 96 / 128`を主に使用する。これはデジタル庁の数値をそのまま採用するものではなく、同庁が示す「余白に一定のルールを持たせ、関係性と視覚的階層を明確にする」という考え方をBashiiin! coffee向けに具体化したもの。

- 同一グループ内：8–24px
- カード内部：24–32px
- セクション内の大ブロック：48–80px
- セクション間：Desktop 96–144px / Mobile 72–104px

### 5.2 Width

- 最大コンテンツ幅：1200px前後
- 本文の最適行長：日本語約24–38文字を目安
- Desktopで写真とテキストを50:50固定にしない。内容に応じ55:45、60:40等を使う

### 5.3 Corners / Elevation

- 角丸：8–16pxを基本。写真は0–12pxの範囲でセクションに応じて使う
- カード影は最小限。基本はborderと背景差で表現
- 大きなドロップシャドウや浮遊カードの多用を避ける

## 6. 共通UIコンポーネント

### 6.1 Button hierarchy

**Primary**
- 塗り：`--ink`
- 文字：白
- 高さ：48–56px
- labelは動詞で開始

**Secondary**
- 白または透明
- `--ink` 1–2px outline
- Primaryとの差を形状で認識できること

**Text link**
- 下線または矢印アイコンを併用

### 6.2 Card

CURRENT BEANS、CULTURE等で使用。

- border：`--line`
- 背景：白
- shadowなし〜極小
- 同種カードは高さ・padding・見出し位置を揃える
- 全カードに写真を強制しない

### 6.3 Form

- labelを常時表示
- placeholderだけで項目名を伝えない
- input height 48px以上
- textareaは5–7行程度
- errorは色＋テキストで表示
- submitは1つのPrimary button
- フォーム全体は最大640–720px程度
- 送信ボタン付近に「入力情報はお問い合わせへの回答のために利用します」等の短い利用目的を常時表示
- Turnstileはフォームの可読性・主CTAを邪魔しない位置に置き、必要な表示を隠さない
- 送信中は二重送信を防ぎつつ、ボタン文言またはprogress表示で処理中と分かるようにする
- 成功時はフォーム内容を再送しにくい明確な完了状態へ切り替える
- 失敗時は入力内容を可能な範囲で保持し、再入力負担を減らす

### 6.4 Navigation

- Desktop：ロゴ＋6項目前後の簡潔なナビ
- Mobile：ハンバーガー
- Current/hover/focusを明確化
- 「LATEST INFO」はutility CTAとしてヘッダー右側に置いてよい

### 6.5 Analytics instrumentation

GA4は正式導入するが、**計測の都合でUIやコピーを不自然にしない**。

- Instagram、Google Maps、主要CTA、問い合わせフォームには、実装時に安定した`id`や`data-*`属性等を付与し、計測対象を識別できるようにする
- 同じ行動を複数イベントで重複計測しない
- 問い合わせ成功時は、ユーザーに明確な完了状態を表示し、その成功状態に対応して`generate_lead`を送信する
- エラー時は成功表示を出さず、`generate_lead`も送信しない
- 氏名・メールアドレス・問い合わせ本文などの入力値を分析イベントへ含めない
- Analytics用の可視バッジ、余分な文言、UI装飾は追加しない

## 7. セクション別デザイン定義

### 7.1 HEADER — 「整理されていて信頼できる」

**雰囲気**：Clean / Utility / Quiet  
**背景**：白または半透明白。スクロール時に薄いborderを出す。  
**見せ方**：ロゴを主役にしすぎず、サイトの道具として機能。  
**禁止**：常時黒背景、極端に大きいロゴ、派手なmenu animation。

### 7.2 HERO — 「営業サンプルの第一印象を、明るく正式版へ」

**雰囲気**：Editorial / Confident / Craft / Warm  
**目的**：スペシャルティコーヒーの店だと一瞬で分かり、営業サンプルとの連続性も感じられる。  
**Desktop構図**：営業サンプルの「大きな写真＋大きな明朝見出し＋英字Eyebrow＋ロゴ」の構成原理を継承する。写真55〜70%程度、白・生成りのコピー面30〜45%程度を目安にした非対称構成。単純な50:50は避ける。  
**Mobile構図**：大きな写真→白いコピー面→CTAの読み順を基本とし、PCを単純縦積みにしない。必要なら写真とコピー面を軽く重ねるが、本文を写真上へ大量に置かない。  
**写真**：抽出・コーヒー・店内の許可済み実写。温かい暗部は残してよいが、黒つぶれを抑え、白いUIとの接続を整える。  
**CTA**：Primary「最新情報をInstagramで見る」、Secondary「お問い合わせ」を基本。  
**装飾**：英字Eyebrow、細いrule、ロゴ、必要最小限の手書き的ディテール。  
**禁止**：全面黒Heroへ戻すこと、一般的な白いEC／カフェテンプレートにすること。

### 7.3 LATEST INFO — 「来店前の不安をすぐ解消」

**雰囲気**：Clear / Helpful  
**背景**：白〜ごく薄いブルーグレー。  
**UI**：短い情報パネル。長文にしない。  
**アクセント**：Blueを小さく使用可能。  
**CTA**：Instagramへの明確なリンク。  
**画像**：必須ではない。情報性を優先。

### 7.4 COFFEE — 「本気度・専門性」

**雰囲気**：Serious / Craft / Editorial  
**背景**：白。必要に応じ薄いcoffee/cream面を一部だけ。  
**写真**：抽出やコーヒーの大判実写。  
**Desktop構図**：左に見出し・短文、中央に大きな写真、右に「スペシャルティコーヒー／ハンドドリップ／丁寧な抽出」等の特徴を整理する3分割を第一候補とする。HEROと同じ2カラムを繰り返さない。  
**Mobile構図**：見出し→大判写真→特徴カード／コンパクトリスト。特徴カードは2列＋1列または横スクロールも可。  
**文字**：大きな明朝系見出し＋小さな英字Eyebrowで営業サンプルの編集感を残す。  
**禁止**：暗い洞窟のような背景、過剰なスモーク・黒グラデーション。

### 7.5 CURRENT BEANS — 「選ぶ楽しさ・情報の信頼感」

**雰囲気**：Precise / Fresh / Product-like  
**背景**：白〜薄いニュートラル。  
**Desktop構図**：説明＋実物パッケージ写真を一方に置き、もう一方に2〜3列の豆カードを配置する。商品一覧として整理し、COFFEEの編集構図と差別化する。  
**Mobile構図**：商品写真の後に、1.1〜1.3枚程度が見える横スクロールカードを第一候補とする。縦1列に長く並べすぎない。  
**カード項目例**：Country / Region / Variety / Process / Flavor。確認済み項目だけ表示。  
**アクセント**：UIはBurnt Orangeを基本とし、商品パッケージ由来の色は写真／グラフィックとして活かす。  
**将来性**：CMS化しても崩れないカード構造。

### 7.6 SWEETS — 「温かさ・休憩感」

**雰囲気**：Warm / Soft / Appetizing / Editorial  
**背景**：白〜Cream `#F3EEE4`を候補。  
**写真**：プリンを主役に、ドリンクや焼き菓子等を大小で組み合わせる。  
**Desktop構図**：説明文＋大写真1枚＋小写真1〜2枚の非対称コラージュを第一候補とする。  
**Mobile構図**：大きな主写真と小さな補助写真を縦方向にずらして配置し、単純な1枚写真＋文章にしない。  
**アクセント**：Orangeは小さく使える。手書き風短文は補助装飾として1要素程度。  
**新作**：情報受領後、「NEW」バッジ等は控えめに追加可。未確定時は枠だけ置かない。

### 7.7 SPACE — 「営業サンプルの深さを残す没入ポイント」

**雰囲気**：Calm / Natural / Immersive / Honest  
**背景**：白〜生成りを基本とするが、このセクションはページ内で例外的に濃いcoffee／ink面を広く使ってよい。  
**写真**：横長・ワイドの実店舗写真を、他セクションより大きく見せる。画面幅を活かした没入構図を優先する。  
**Desktop構図**：短いコピー＋ワイド写真。写真面積を広く取り、カードの中に小さく閉じ込めない。  
**Mobile構図**：画面幅いっぱいに近い大写真を使い、前後に短いコピーを置く。  
**文字**：体験を断定せず、空間の視覚情報を補う短文。  
**禁止**：写真を必要以上に暗く加工してバー感を強めること。

### 7.8 CULTURE — 「ここだけ少し遊ぶ」

**雰囲気**：Playful / Editorial / Community  
**背景**：白ベース。UIアクセントはBurnt Orange中心。商品やグッズ写真の色はそのまま活かす。  
**Desktop構図**：グッズ写真やパッケージ写真を使った非対称コラージュ＋「オリジナルグッズ／コーヒーギフト／イベント・カッピング」等のアイコンカード。  
**Mobile構図**：大きな写真1枚＋2列または縦のコンパクト情報カード。  
**ルール**：斜め配置やステッカーは1〜2要素まで。色をUI側で増やしすぎない。  
**目的**：コーヒー店の信頼感を壊さず、営業サンプルにあった文化的な個性を正式版で整理して見せる。

### 7.9 INSTAGRAM / JOURNAL — 「最新情報への橋渡し」

**雰囲気**：Editorial / Current  
**背景**：白。  
**レイアウト**：3〜6枚程度の許可済み実写をグリッドまたは横スクロール。  
**CTA**：アカウント名と「Instagramを見る」を明確にする。  
**禁止**：API連携しているように誤認させる表現。

### 7.10 CONTACT — 「安心して送れる」

**雰囲気**：Simple / Trustworthy / Quiet  
**背景**：薄いneutral/cream面でページ終盤に区切りを作る。  
**フォーム**：1カラム、最大幅640–720px。  
**説明**：「お問い合わせはこちら」程度の短文。  
**ボタン**：Primary 1つ。  
**送信状態**：送信中／成功／失敗を明確に表示。成功時の表示はGA4の`generate_lead`計測と対応させる。  
**個人情報表示**：送信ボタン付近に、入力情報を問い合わせ対応のために利用する旨を短く明示する。  
**bot対策**：Turnstileの表示領域を確保し、UI全体より目立たせない。ただし必要な検証表示は隠さない。  
**禁止**：営業・予約機能があると誤認させる文言。

### 7.11 FOOTER — 「情報を静かに閉じる」

**雰囲気**：Minimal / Utility  
**背景**：`--ink`の暗色を使ってよい唯一の大面積候補。ただし黒一色で重くしすぎない。  
**掲載**：ロゴ、住所、Instagram、Map link、Copyright。  
**注意**：ACCESSセクション化しない。地図埋め込みは不要。

## 8. 写真ディレクション

### 8.1 写真の優先順位

1. コーヒー・抽出
2. 豆
3. 店内・カウンター
4. スイーツ
5. グッズ・イベント・カルチャー

### 8.2 仕上げ

- 過度に暗くしない
- 白背景との接続を意識し、黒つぶれを抑える
- 彩度を上げすぎない
- 木・コーヒー・肌色等の自然な色を残す
- 同じ写真を複数セクションで繰り返さない
- 実店舗写真の内容をAIで改変しない
- 元写真が暗い場合は、露出・シャドウ・ホワイトバランス・局所コントラストを調整し、白基調のUIに接続しやすくする
- 木の温かさ、コーヒーの深い色、実店舗の質感は残し、昼間の別店舗のような不自然な明るさにはしない
- 写真編集で存在しない商品・設備・人物・ロゴ・装飾を追加しない

---

## 9. モバイルデザイン

モバイルを最優先で成立させる。**Desktop版を単純に縦積みした構成にはしない。**

- 1画面に情報を詰め込みすぎない
- HEROのコピーは3〜5行以内。大写真→白いコピー面→CTAの読み順を明確にする
- CTAは原則縦積みまたは2ボタンまで
- COFFEEは大判写真＋特徴カード／リストで情報密度を変える
- Current Beansは横スクロールカードを第一候補とし、1.1〜1.3枚程度が見える設計も可
- SWEETSは主写真＋補助写真の大小コラージュでリズムを作る
- SPACEは画面幅いっぱいに近い写真を使い、スクロール途中の没入ポイントにする
- CULTUREは写真＋コンパクトなカードで、読み順を明確化する
- Instagramは2列グリッドまたは横スクロールで短く見せる
- フォームは全幅
- 固定CTAを使う場合は1〜2個まで。本文を隠さない
- safe-areaを考慮
- 375/390/430pxでモックを確認する

---

## 10. アニメーション

- Fade / Reveal：250–500ms程度
- easingは自然で速め
- Scroll Revealは情報を隠しすぎない
- hoverは色・border・1〜2px程度の移動に限定
- Parallaxは原則不要
- marqueeはCULTUREで使う場合も1箇所まで
- `prefers-reduced-motion`で無効化または大幅短縮

## 11. 完成イメージ画像を作る際の固定条件

後工程のAI画像生成・モック制作では、以下を必ずプロンプトに含める。

### 11.1 Desktop mock

- 実在Webサイトとして実装可能な1440px幅の縦長LP
- 白・温かい白を中心に、写真主役
- HEROは暗い全面写真にしない
- スペシャルティコーヒーを最上位の視覚階層にする
- CURRENT BEANSはUIカード
- SWEETSはcream背景
- CULTUREだけ少しeditorial/playful
- ACCESSセクションなし
- CONTACTフォームあり
- Footerに住所・Instagram・Map link
- デジタル庁／PayPayそのもののブランドUIをコピーしない

### 11.2 Mobile mock

- 390px程度の縦長Web UI
- 写真→コピー→CTAの読み順が明確
- 見出しが過剰に大きくない
- 余白を十分に取り、情報密度を抑える
- Current Beansは1列カード
- Contactは全幅フォーム
- Footerまで自然なリズムでつなぐ

### 11.4 作成済みデザインリファレンスの扱い

- 作成済みデザインリファレンスは、正式版の各セクション構図・余白・写真比率・明暗バランスを確認する視覚参考として使用する
- デザインリファレンスをピクセル単位でそのまま再現する必要はない。実素材・実コピー・レスポンシブ・アクセシビリティに合わせて調整する
- 先方が評価した営業サンプルとの連続性が失われる場合は、デザインリファレンスより営業サンプルのデザインDNAを優先して再調整する
- 本書または要件定義書と競合する表現・商品・価格・店舗情報がリファレンスに含まれる場合、その情報は採用しない
- 完成イメージ画像は承認用の視覚資料であり、未確認情報を事実化する根拠にはしない

### 11.3 モックで禁止するもの

- ポスターのように文字を詰め込む
- 存在しない商品名・価格・豆情報を勝手に生成
- AI生成の店舗・人物・商品を実写として描く
- dark luxury cafeのテンプレート化
- ACCESS/Mapの大セクションを復活させる
- スマホで読めない小文字

## 12. デザインレビュー基準

完成イメージ・実装ともに、次の質問でレビューする。

1. 3秒でスペシャルティコーヒーの店だと分かるか
2. 白基調でも無個性になっていないか
3. 「暗い・隠れ家」に戻っていないか
4. 写真が主役で、UIが写真を邪魔していないか
5. COFFEEとCURRENT BEANSが最も強く見えるか
6. CULTUREだけ適度に遊び、全体を壊していないか
7. Primary / Secondaryの行動が明確か
8. モバイルで読み順が迷わないか
9. フォームは安心して入力できるか
10. 色・余白・ボタン・カードが一貫しているか
11. コントラスト、focus、target sizeに問題がないか
12. 店舗が確認していない情報をデザインで事実化していないか
13. GA4計測のためにUI・コピーが不自然になっていないか
14. フォームの成功・失敗状態が視覚的にも明確か
15. 営業サンプルLPを見た人が「同じブランドの正式版」と感じられるか
16. 一般的な白いカフェテンプレートへ寄りすぎていないか
17. 各セクションの構図に変化があり、長いLPでも単調になっていないか
18. 白基調と深い店舗写真の対比が、暗すぎず軽すぎないバランスになっているか
