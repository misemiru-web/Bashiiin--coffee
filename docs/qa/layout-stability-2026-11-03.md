## 1. 総合判定

**A：改善完了（ローカルChrome・今回の初期表示試験の範囲）。**

正式なセッションウィンドウ方式で計算した初期表示CLSは、修正前最大 **0.410906** → 修正後 **0**。全5ページ×6幅×通常／遅延読み込み×各2回＝修正前120回・修正後120回を比較した。修正後は全120回で0.1以下となった。実機・実回線・公開後のp75値の達成を意味しない。

### 前報告の「約0.395」の訂正

前回のスクリプトは、`PerformanceObserver` の `layout-shift` エントリーから `hadRecentInput=false` の `value` を単純合算していた。これはピクセル距離ではなく、影響領域と移動距離から算出される**無次元のレイアウトシフトスコア合計**である。セッションウィンドウを実装していなかったため、正式なCLSとして報告した前回の表現を訂正する。

また、保存されていた前回の `browser.json` を再集計すると最大は **0.410021（768px / COFFEE）**。「約0.395」は1024pxの値で、全ケースの最大ではなかった。旧エントリーに時刻がないため、当時の正確なウィンドウ方式CLSは再構成できない。今回の計測は別の試験として区別する。

CLSは、直前の入力に伴う移動を除外し、移動間隔1秒未満・最大5秒のウィンドウごとにスコアを合算し、その最大値を採る。[GoogleのCLS定義](https://web.dev/articles/cls) に基づく。本調査では単純合計 `sum` と正式な `cls` を別々に保存した。

実例：画像だけを遅延させた1024px / COFFEEでは、単純合計 **0.184656** に対して、1秒以上離れた2移動を別ウィンドウに分けたCLSは **0.131335**。両者は常に同じ値ではない。

## 2. 原因と計測根拠

PlaywrightのルーティングでJSと画像の応答を別々に遅らせ、各フレームの寸法、画像の読み込み状態、loadイベント、移動時刻と移動要素の前後座標を記録した。移動要素だけを原因と推測せず、その直前の寸法変更と単独条件の再現を照合した。

| 原因 | 修正前の実測 | 単独条件による切り分け | 判定 |
|---|---|---|---|
| 写真の高さが読み込み前に確保されない | 1024pxのCOFFEE / SPACE画像が高さ0px → 504px。直下の説明が画面外へ移動 | 画像応答を1500ms遅延し、画像loadと同フレームの移動を確認。COFFEEでは約1534msに0.131335の移動 | `aspect-ratio: auto` がHTML寸法由来の比率を上書きし、自然寸法の判明まで高さ0になる |
| 静的ナビをJS初期化時に隠す | 390pxのヘッダー185px → 81px、mainのYも185 → 81。1024pxでは141 → 81 | JSのみ800ms遅延したCONTACTで約828msに0.105156。本文写真のないページでも再現 | フォールバック用ナビが最初に通常フローへ描画され、その後 `menu.hidden=true` で取り除かれる |
| HERO再生ボタンの領域追加 | 1440pxで操作行8px → 52px、直下の紹介文Yが684.5 → 728.5（44px下移動） | JSのみ800ms遅延で0.005840。ギャラリー初期化だけを無効にした別試験では0。通常の初期化時にボタンがhiddenから表示へ変わる瞬間と一致 | 写真トラックの横移動ではなく、初期化時に現れる操作ボタンの高さが原因 |
| Webフォント | 全計測で外部フォント取得0、`document.fonts` のFontFace定義も0 | CSSの@font-face／外部フォント指定もなし | 今回の原因から除外。OSフォントを使用 |

追加の画像待機試験では、1024pxのSWEETSも修正前0px → 504px、修正後は読み込み前後とも504pxだった。CULTUREは修正前から`auto 1450 / 960`が有効で、504pxを予約できていたため変更していない。

写真の`width` / `height`自体は既にHTMLにあった。問題は画像ファイルの欠損や未最適化ではなく、後段CSSの比率上書きだった。SPACE / SWEETS / COFFEEの3規則を対象とし、既存の高さ上限・object-fit・トリミングを維持した。

### SEO改善との関係

- `HEAD=73803d8` のHTML / CSS / JSをブラウザー内だけで配信し、390 / 1024 / 1440px×5ページの15ケースで比較した。checkout・reset・履歴変更はしていない。
- SEO本文拡充前のcommitにも、同じ3つの画像比率上書き、通常フローのナビを後から隠す処理、再生ボタンのhidden切替が存在する。
- 同commitでも390px CONTACTで0.105156、1024px ABOUTで0.313086・COFFEEで0.281846、1440px TOPで0.005989のCLSを再現した。
- よって、今回特定した3原因は**既存実装由来**。SEO本文量によって写真や説明の初期位置・影響領域が変わるため、前後のスコアが同一になるとは限らない。コピー削除で写真を画面外へ追い出す対応は行っていない。

生データ：[原因切り分け](layout-stability-2026-11-03/causes.json)、[全計測・旧commit比較](layout-stability-2026-11-03/measurements.json)。原因切り分けには時刻・前後rect・フレームごとの画像寸法・load時刻を含む。
